# 工作簿结构

脚本按工作表名称和表头文字定位，不依赖固定行号。名称需要同时包含“产品利益信息”和“结果”（或“底稿”）。

## 结果表（产品利益信息——结果）

每个“产品 × 保险期间 × 交费期”组合一行。

| 列 | 内容 |
|---|---|
| B | 产品序号（同一产品只在第一行写，后续行留空） |
| C | 产品名称 |
| D | 利益类型：`固收` 只填保证三项；`分红` 九项都填 |
| E | 保险期间，例如 `终身`、`保至105周岁；60岁起年领`、`10年` |
| F | 交费期，例如 `趸交`、`5年` |
| G | 最高投保年龄 |
| H:J | 保证 IRR、保证返本年度、保证翻倍年度 |
| K:M | 累积生息 IRR、返本、翻倍 |
| N:P | 交清增额 IRR、返本、翻倍 |
| Q | 口径标记（逐行） |

H:P 全部是公式，指向底稿汇总行的 L:T，例如 `=产品利益信息——底稿!L466`。**不要把结果表的公式改成数值。**

占位文字：

| 文字 | 含义 |
|---|---|
| 以 `待补` 开头（待补现价、待补演示、待补红利…） | 还没有数据，是要填的对象 |
| `-` | 不适用（固收产品的分红指标） |
| `无60/65岁起领`、`40岁不可投保` | 该组合在本口径下不存在，不是待补 |
| `期内未达`、`105岁内未达` 等 | 已有完整逐年数据，在数据范围内没有达到 |

## 底稿（产品利益信息——底稿）

自上而下三段：

1. **参数行**：A 列为“保费（元）”的那一行。B=保费，D=年龄，F=性别，H=红利累积利率，J=演示利率。
2. **汇总区**：表头行 A 列为“原序号”。每个组合一行：

   | 列 | 内容 |
   |---|---|
   | A / B | 产品序号 / 名称 |
   | G | 保险期间 |
   | J | 交费年数（趸交=1） |
   | K | 最高投保年龄 |
   | L:T | 九项指标（公式，指向该组合的逐年块；没有数据时是“待补…”文字） |
   | U | 口径备注 |
   | AC | 来源 |

3. **逐年区**：表头行 A 列为“组合号”。每个组合一个逐年块，保单年度 0 到 N 各一行：

   | 列 | 内容 | 性质 |
   |---|---|---|
   | A / B | 组合号 / 产品序号 | 数值 |
   | C | 保单年度末（0 = 投保时） | 数值 |
   | D | 期初交费 `=IF(C<$J$汇总行,$B$参数行,0)` | 公式 |
   | E | 保证现金价值（年金为当年给付后） | 数值 |
   | F | 当年保证生存金/年金 | 数值 |
   | G | 当年保证满期金 | 数值 |
   | H | 来源披露的现金价值原值 | 数值 |
   | I | 累计已领 `=I上一行+F` | 公式 |
   | J | 累计已交 `=MIN(C,$J$汇总行)*$B$参数行` | 公式 |
   | K | 保证总利益：年金 `=E+G+I`；寿险 `=H` | 公式 |
   | L | 保证净现金流 `=-D+F+G+IF(C=O,E,0)` | 公式 |
   | M / N | 返本 / 翻倍标记（1 或 0） | 公式 |
   | O | IRR 终点年度 | 数值 |
   | P | 累积红利余额 | 数值或“未披露” |
   | Q / R | 累生总利益 `=K+P` / 累生净现金流 | 公式 |
   | S / T | 累生返本 / 翻倍标记 | 公式 |
   | U | 含交清增额的总现金价值 | 数值或“未披露” |
   | V / W | 当年红利年金 / 红利满期金 | 数值 |
   | X / Y | 增额总利益 / 增额净现金流 | 公式 |
   | Z / AA | 增额返本 / 翻倍标记 | 公式 |
   | AB | 当年红利 | 数值 |
   | AE:AG | 产品名称、保险期间、交费期 | 文字 |
   | AH | `结果表第n行引用（底稿汇总行第m行）` | 文字 |

汇总行公式的标准形式：

```
IRR        =IRR(L起:L终点)            （累生用 R 列，增额用 Y 列）
返本/翻倍  =INDEX(C起+1:C末,MATCH(1,M起+1:M末,0))
未达到     =IF(COUNTIF(M起+1:M末,1)=0,"105岁内未达","核查错误")
```

工作簿里有少量组合用的是别的判定方法（例如用上下界证明翻倍年度落在某一年），它们的汇总公式不是上面的形式，口径写在该行标注里。`audit`/`verify` 会把这些单独计数（`judged_by_other_method`），不会改动它们。

## 脚本怎么写入

- 已有逐年块的组合：往 P、AB（累积生息）和 U、V、W（交清增额）填数，补上 Q:T、X:AA 的公式，把汇总行对应的三格从“待补”换成公式。
- 没有逐年块的组合：在底稿末尾追加一个完整的块（样式取自上一个块的末行），汇总行 L:N 换成公式。
- 结果表：只更新 H:P 的缓存值（公式不变）和 Q 列标注。
- 所有公式单元格同时写入计算结果，文件不经 Excel 重算也能直接读数；但只有 Excel 重算才能证明公式正确，所以必须运行 `verify`。
